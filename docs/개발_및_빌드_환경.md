# 개발 및 빌드 환경 가이드

이 문서는 저장소 루트에서 실행하는 Windows/PowerShell 기준의 재현 가능한 개발·빌드 환경을 정리한다. 경로는 모두 저장소 루트 기준 상대 경로 또는 PowerShell의 `$PWD`를 사용한다.

## 기술 기준선

| 구분 | 버전 또는 기준 | 설정 위치 |
| --- | --- | --- |
| JDK | 17 | Gradle/AGP 실행 JDK |
| Gradle Wrapper | 9.6.0 | `gradle/wrapper/gradle-wrapper.properties` |
| Android Gradle Plugin | 9.4.0 | `gradle/libs.versions.toml` |
| Kotlin | 2.4.20 | `gradle/libs.versions.toml` |
| Android compile SDK | 37 | `app/build.gradle.kts` |
| Android target/min SDK | 36 / 26 | `app/build.gradle.kts` |
| Compose BOM | 2026.08.00 | `gradle/libs.versions.toml` |

AGP 9.4의 Gradle/JDK 호환 기준은 [공식 호환표](https://developer.android.com/build/releases/agp-9-4-0-release-notes), Gradle 변경점은 [Gradle 9.6 릴리스 노트](https://docs.gradle.org/9.6.0/release-notes.html)를 따른다.

## 사전 조건

1. JDK 17을 설치하고 `JAVA_HOME`과 `PATH`를 설정한다.
2. Android SDK command-line tools를 저장소의 `./.android-sdk/cmdline-tools/latest`에 배치한다.
3. 저장소 루트 PowerShell에서 Android SDK 위치를 설정한다.

```powershell
$env:ANDROID_HOME = (Join-Path $PWD '.android-sdk')
```

4. 필요한 SDK 패키지를 설치한다.

```powershell
& "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat" --licenses
& "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat" "platform-tools" "platforms;android-37.0" "build-tools;37.0.0"
```

`.android-sdk/`와 `local.properties`는 Git에서 제외된다. `local.properties`의 `sdk.dir`은 각 PC의 절대 경로가 될 수 있으므로 공유하거나 커밋하지 않는다. 위 `ANDROID_HOME` 설정을 사용하면 저장소 내부의 상대 SDK 경로로 빌드할 수 있다.

## 환경 확인

저장소 루트에서 다음을 실행한다.

```powershell
java -version
.\gradlew.bat --version --no-daemon
```

두 번째 명령은 Gradle 9.6.0 및 JDK 17을 표시해야 한다. 잘못된 wrapper URL, JDK 미설치, 또는 다운로드 실패는 0이 아닌 종료코드로 끝나야 한다.

## 기본 빌드

처음 빌드하거나 의존성 캐시가 비어 있을 때는 네트워크 연결 상태에서 실행한다.

```powershell
$env:ANDROID_HOME = (Join-Path $PWD '.android-sdk')
.\gradlew.bat build --no-daemon
```

의존성을 이미 받아 둔 뒤에는 외부 다운로드 없이 재현하려면 `--offline`을 추가한다.

```powershell
$env:ANDROID_HOME = (Join-Path $PWD '.android-sdk')
.\gradlew.bat build --offline --no-daemon
```

## 자주 사용하는 검증 명령

| 목적 | 명령 |
| --- | --- |
| simulation 단위 테스트 | `.\gradlew.bat :core:simulation:test --no-daemon` |
| Phase0 아키텍처 검사 | `.\gradlew.bat verifyPhase0Architecture --no-daemon` |
| debug APK 생성 | `.\gradlew.bat :app:assembleDebug --no-daemon` |
| Android lint | `.\gradlew.bat :app:lintDebug --no-daemon` |
| 계측 테스트 소스 컴파일 | `.\gradlew.bat :app:compileDebugAndroidTestKotlin --no-daemon` |
| 연결 기기 계측 테스트 | `.\gradlew.bat :app:connectedDebugAndroidTest --no-daemon` |

`connectedDebugAndroidTest`는 연결된 Android 기기 또는 실행 중인 emulator가 있어야 한다. Compose 테스트는 `ui-test-junit4`와 debug 전용 `ui-test-manifest`를 사용한다. 설정 방식은 [Compose 테스트 공식 문서](https://developer.android.com/develop/ui/compose/testing)를 따른다.

## 저메모리 CI 재현성

`gradle.properties`는 `org.gradle.workers.max=1`을 고정한다. 이는 debug·release·계측을 `--rerun-tasks`로 함께 실행할 때 R8/D8 메모리 경쟁을 피하기 위한 Phase 0 기준선이다.

```powershell
.\gradlew.bat --offline --no-daemon --rerun-tasks check :app:lintDebug :app:assembleDebug :app:assembleRelease :app:connectedDebugAndroidTest
```

## 산출물과 보고서

| 항목 | 상대 경로 |
| --- | --- |
| debug APK | `app/build/outputs/apk/debug/app-debug.apk` |
| lint HTML 보고서 | `app/build/reports/lint-results-debug.html` |
| simulation 테스트 XML | `core/simulation/build/test-results/test/` |
| Android 계측 테스트 컴파일 클래스 | `app/build/intermediates/built_in_kotlinc/debugAndroidTest/` |

`build/` 하위 산출물은 재생성 가능하므로 커밋하지 않는다.

## 의존성 lockfile 갱신

의존성 버전을 의도적으로 변경한 경우에만 아래 명령으로 lockfile을 갱신한다.

```powershell
$env:ANDROID_HOME = (Join-Path $PWD '.android-sdk')
.\gradlew.bat :core:simulation:test :app:assembleDebug --write-locks --no-daemon
```

생성되는 lockfile은 `settings-gradle.lockfile`, `app/gradle.lockfile`, `core/simulation/gradle.lockfile`이다. 의존성을 바꾸지 않은 작업에서 lockfile을 재생성하거나 수동 편집하지 않는다.

## Windows IPC 문제의 한시적 우회

일부 제한된 Windows 실행 환경에서 Gradle/JDK가 Unix-domain socket을 만들지 못해 `SocketException` 또는 `Invalid argument`로 시작 단계에서 실패할 수 있다. 일반 PC에서는 설정하지 말고, 해당 오류가 재현될 때만 현재 저장소의 상대 경로를 이용해 TCP fallback을 유도한다.

```powershell
$env:JAVA_TOOL_OPTIONS = "-Djdk.net.unixdomain.tmpdir=$(Join-Path $PWD '.gradle\disabled-unix-domain-socket')"
.\gradlew.bat build --no-daemon
Remove-Item Env:JAVA_TOOL_OPTIONS
```

`disabled-unix-domain-socket` 디렉터리는 만들지 않는다. 이 설정은 현재 PowerShell 프로세스에만 적용되며 프로젝트 설정 파일에 저장하지 않는다.
