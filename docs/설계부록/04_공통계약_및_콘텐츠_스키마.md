# 공통 인터페이스 / 콘텐츠 정의 / SQL 적용 규약

### 공통 계약의 적용 범위
모든 새 메소드/클래스명과 물리 DDL 은 **설계 보완안**이다. 제공된 자료에는 실제 저장소·DAO·SQL 이 없으므로 기존 구현에 대한 변경 완료를 뜻하지 않는다. 원문의 객체명/데이터 항목은 최대한 유지하며 기존 코드가 발견되면 adapter 로 연결한다.

### 구현 명명 규칙

Phase 번호는 일정·관리 식별자이며 도메인 책임이 아니다. 새 production 클래스·인터페이스·메소드·DTO·Compose 화면명에는 `Phase0`, `Phase1`, `Phase2`와 같은 Phase 접두사·접미사를 사용하지 않는다. 이름은 기능·도메인 책임을 표현한다(예: `TimeAdvanceController`, `TimeAdvanceViewState`). 기존 이름은 호환성 때문에 유지할 수 있지만, 명칭 변경은 해당 Phase의 별도 Rename Batch로 처리하고 동작 변경과 섞지 않는다. 테스트·문서 anchor·관리 Task ID의 `P{n}` 표기는 추적용이므로 이 규칙의 대상이 아니다.

`CommandEnvelope(commandId, sessionEpoch, expectedVersion, actorId, payload, payloadHash)`는 외부 **gameplay** mutation UseCase에서만 사용한다. INTERNAL pure calculation과 LIFECYCLE/CONTROL operation은 envelope·command receipt·gameplay DomainEvent를 직접 만들지 않고, 필요하면 enclosing gameplay command의 immutable calculation 또는 safe-boundary control로 참여한다. `payloadHash`는 `CommandPayloadCodec.v1`의 canonical JSON(NFC UTF-8, object key 정렬, 정수/enum/ID canonical 표현, float 금지)에 domain prefix와 codecId를 붙여 SHA-256으로 계산하며 외부 입력값을 신뢰하지 않는다. 세부 byte 계약은 [84 Command/Event 계약](../84_전체_Command_Event_계약서.md)을 단일 기준으로 삼는다. `GameMinute`, `CombatMillis`, `Money(Long)`, `BasisPoint`, `EntityId`는 혼합 연산을 금지한다. 확률의 기본 표현은 **ppm(0..1,000,000)**이며 세밀한 0.01%도 정수로 표현한다. 표시 반올림과 판정은 분리한다. 정수연산 overflow 는 오류이며 clamp 로 은폐하지 않는다.

`ReadView`와 `DomainDelta`는 불변이다. `DomainDelta`는 typed aggregate change·RNG 새 상태/counter·typed domain event·command result만 포함하며 table/DAO/SQL/`dirtyRows[]`를 포함하지 않는다. SaveCoordinator가 이를 persistence plan과 dirty shard key로 변환한다. 콘텐츠 참조/외부 파일 읽기는 transaction 진입 전에 끝낸다. 실패 가능한 대규모 계산은 transaction 밖에서 하고, 성공한 커밋 이후에만 메모리 및 화면 상태를 게시한다. `stateHash`의 포함 테이블, 제외 열, 타입별 byte encoding, 계산 시점은 [84의 `StateHash.v1`](../84_전체_Command_Event_계약서.md)을 따른다. v1은 checkpoint/load/test에서 전체 계산하며 실측 전 증분 hash 구조를 추가하지 않는다.

중복 명령은 동일 epoch/commandId 와 payload hash 를 함께 검사한다. 동일 ID/동일 payload 이면 이전 결과를 반환하고, 다른 payload 이면 `IdempotencyKeyReuse`를 반환한다. 인메모리 중복 제거만으로 복구 후 중복을 막았다고 판단하지 않는다.

게임은 한 프로세스·한 활성 WorldSession 을 기준으로 한다. 여러 노드/서버/분산 Lock 은 **해당 없음**이다. 다만 UI 연속 탭·코루틴 완료·예약 이벤트·슬롯 전환·프로세스 재실행 간의 동시성은 실제로 검증한다.

물리 소유는 `WorldSession`·`WorldEngine`·`SavePort` 계약=`:core:simulation`, `SaveCoordinator : SavePort` 구현=`:core:save`, Android 조립=`:app`, JVM 조립=`:tools:headless`다. feature는 `WorldSession.execute`와 typed ReadPort만 사용하고 `WorldEngine`·`SaveCoordinator`·DAO·mutable Repository를 직접 참조하지 않는다. `WorldEngine`은 `SavePort`에만 의존하며 구체 저장 구현과 Room을 모른다.

## DTO 타입 원칙
입력 enum 은 Sealed/명시 Enum 으로파싱하고알수없는값은 Compatibility 오류로처리한다. templateId 는 contentVersion 에결합된정적참조,instanceId 는개별소유/이력을가진동적참조이다. 이름/표시텍스트를 PK 로사용하지않는다. 공통 reference enumerator 는모든 ID 참조를검사하고보호대상을 GC 전에표시한다.

## 콘텐츠 스키마
`ContentTemplate(id,kind,sourceDisplayName,displayNameOverride,displayName,grade,minLevel,tags,enabled,definitionVersion,definition)` envelope 를 공통으로 사용한다. `id`는 canonical `sourceId` 그 자체이며 별도 `sourceId/source_id` 필드나 컬럼을 두지 않는다. `kind`는 P1 `ContentKind.v1`의 직렬화 코드(`ACC, ARM, BOS, CHAIN, CTR, DNG-EVT, EPRE, ESUF, EVT, ITM, LEG, MON, MPRE, MSUF, REL, SET, SKL, SPRE, SSUF, WPN`)다. `definition`에는 `unresolved: UnresolvedField[]`를 둘 수 있으며 각 원소는 `code,field,sourceText,reason`을 가진다. 아래 ITEM/WEAPON 같은 이름은 definition family를 설명하는 개념명이며 저장 코드가 아니다. definition은 아래 유형별 검사를 통과해야 한다.

원천 catalog의 `권장 레벨`은 `recommendedLevel`이며 실제 사용 제한인 `minLevel`로 승격하지 않는다. 원문 효과 문자열은 evaluator가 직접 실행하지 않고, C10·87의 typed Effect AST로 완전히 변환된 경우만 활성화한다. 표의 `unresolved`는 의미를 임의 추정하지 않았다는 machine-readable 증거다.

| `EVT` | `NpcWorldEventV1(category,name,eligibilityAST,choices,effects)` | 원천 c2=category, c3=name; 조건/선택/효과 설명형이면 비활성 |
| `DNG-EVT` | `DungeonEventV1(category,name,eligibilityAST,choices,effects)` | 원천 c2=category, c3=name; choice outcome 미제공 시 비활성 |
| `CHAIN` | `EventChainV1(category,name,steps,finalEffects)` | 원천 c2=category, c3=name; step ID/조건/복구 미제공 시 비활성 |
| `LEG` | `LongEventV1(name,eligibilityAST,scenario,chronicleTags)` | time domain·조건·scenario effect 미확정 시 비활성 |

Profile 규칙은 닫혀 있다. `PROTOTYPE`은 unresolved row를 보존할 수 있지만 반드시 `enabled=false`이고 활성 콘텐츠에서 reachable하면 실패한다. `ALPHA`는 reachable row의 unresolved가 0이어야 한다. `FULL`은 전체 unresolved와 dangling reference가 0이어야 한다. 20종 모두 고정 열 수와 종류별 이름 열을 검사하며 `EVT`,`DNG-EVT`,`CHAIN`의 category를 이름으로 오인하지 않는다.

`DefinitionHash.v1`은 `kind,id,definitionVersion,grade,minLevel,sorted tags,enabled,canonical definition`의 canonical JSON SHA-256이다. `sourceDisplayName`, `displayNameOverride`, effective `displayName`, provenance/raw row는 gameplay hash에서 제외한다. 표시명만 바뀌면 global `logicalContentHash`는 바뀔 수 있으나 required definition hash는 유지되어 compatibility 결과는 `Compatible`이다. Phase 1 승인 전 계약 보완이므로 별도 배포된 구 codec은 없으며 이 투영을 V1 기준선으로 삼는다.

## 명령 처리 pseudocode
```kotlin
suspend fun execute(e: CommandEnvelope): CommandResult = worldActor.serial {
    requireEpoch(e.sessionEpoch)
    require(e.payloadHash == commandPayloadCodec.hash(e.payload))
    receiptPort.find(e.sessionEpoch, e.commandId)?.let { old ->
        require(old.payloadHash == e.payloadHash)
        return@serial old.result
    }
    val before = immutableSnapshot()
    requireVersion(e.expectedVersion, before.version)
    val delta: DomainDelta = dispatcher.validateAndCompute(e, before, boundContent)
    invariantChecker.check(before, delta)
    val receipt = savePort.commit(e, delta) // :core:save의 SaveCoordinator가 구현
    publish(delta.toCommittedSnapshot(receipt))
    receipt.result
}
```
위는 일반 원자 command의 제어흐름 계약이며 라이브러리 대입만으로 컴파일되는 완성소스코드가 아니다. guard에서 결정론적으로 거절된 유효 envelope는 권위상태/RNG 변경 없이 receipt-only transaction으로 REJECTED를 확정하며, malformed/stale/key-reuse/infrastructure 실패는 receipt를 만들지 않는다. 시간 진행 같은 resumable command는 [84의 segment commit 계약](../84_전체_Command_Event_계약서.md)을 사용한다. 각 Phase 메소드의 입력/반환/필드/SQL/오류와 함께 실제 Kotlin으로 구현한다.

## DDL 적용
content/save schema SQL 은별도 DB 로실행한다.코드가없는상태에서설계스키마구문만확인할수있으며 RoomEntity 생성/API 호환/실제 migration 의검증은추가필요하다. row_version 은 optimistic 조건이지 DB 분산 lock 이아니다.유일키에 NULL 이들어가면중복이허용될수있으므로멱등키필드는 NOT NULL 로선언한다.
