# 94. 설계 보완안 및 결정대장

> v31.2 · 확정 원문과 제안 구분. 2026-09-09 사용자의 최적안 일괄 결정 승인으로 C01~C22 설계 선택안을 모두 기준선에 반영했다. 실제 저장소·실물 자산·실기기 측정 증거는 별도 Gate이며 승인된 설계 결정을 미결정으로 되돌리지 않는다.

## 1. 근거 우선순위
현재 첨부 문서의 명시적 최종/대체 조항, 동일 범위의 상세 조항, 개요/초기 예시 순으로 해석한다. 번호가 크다는 이유만으로 자동 덮어쓰지 않는다. 모순의 범위가 명확하지 않으면 양쪽을 보존하고 결정 대기로 둔다. 이전 대화나 사용자 메모를 첨부 자료에 없는 범위를 추가하거나 최신 첨부 규칙을 변경하는 근거로 사용하지 않는다.

## C19. 장기성능/용량 목표와단말기준

| 항목 | 설계 |
|---|---|
| 상태 | 승인·BASELINE_V1 / 실기기·장기 Test NOT_RUN |
| 근거 | §2478/§2510/§3103/§3124 |
| 결정/보완 내용 | [85 NFR](85_NFR_성능_용량_단말_기준서.md)을 `BASELINE_V1`으로 고정한다. MIN은 API 26/arm64/RAM 4GB/60Hz/가용 4GB, STD는 API 36/arm64/RAM 8GB/60·120Hz/가용 8GB다. 사용자 여정의 기존 P95 목표를 승인하고, 안정 상태 PSS는 MIN 384 MiB 이하·일시 peak 512 MiB 이하, 100년 compact export 128 MiB 이하, 300년 256 MiB 이하, live save 총량은 같은 fixture compact export의 1.5배 이하로 둔다. |
| 결정자/검토자 | 제품 책임자 / Performance·Save 책임자 |
| 구현영향 | P17, P21, P24, P25 |
| 차단되는 작업 | 설계 결정은 완료했다. P17 scale gate, P24 최적화 gate, P25 RC는 동일 signed release build와 실제 MIN/STD 단말의 측정 PASS 또는 기한·영향·복구안이 있는 명시 예외 승인 전까지 닫히지 않는다. |
| 대안 | 기기 모델명을 영구 규칙으로 고정하면 단종과 OS 업데이트에 취약하므로 하드웨어/OS profile을 계약으로 삼고 실제 제조사·모델·SoC·build fingerprint는 매 실행 증거에 기록한다. |
| 승인 증거 | 2026-09-09 사용자 최적안 일괄 승인. 수치와 측정 프로토콜은 승인했으며 benchmark, PSS, save growth 결과는 NOT_RUN이다. |
| 종결 조건 | 설계 결정 종결. 실측 실패는 목표를 자동 완화하지 않고 먼저 원인 개선 후 재측정하며, 예외가 필요하면 C19 revision으로 별도 승인한다. |
