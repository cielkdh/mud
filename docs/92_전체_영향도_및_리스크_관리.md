# 92. 전체 영향도 및 리스크 관리

> v31.0 · 실제 기존 저장소 미제공: 아래는 **설계상 예상 영향**, 운영코드에서 확인된 변경 사실이 아님.

## 1. 변경 영향 원칙
기존 모듈/SQL/DAO 가있으면먼저책임과호출경로를조사한다.제안메소드로전부이름을바꾸는리팩토링을하지않는다.호환 adapter→국소구현→조건부활성→구 fixture 회귀→migration 검증순서다.게임은오프라인싱글이므로서버데몬/분산노드/네트워크 API 에대한영향은해당없음이다.

## 3. Phase별 위험 대장

아래 전체 표는 누락 방지용 catalog이며 모두 같은 우선순위가 아니다. 발생가능성은 실측이 아닌 초기 평가다. 실명 담당자는 Task 착수 전에 배정하되 accountable 역할은 아래 우선대장에서 고정한다.
